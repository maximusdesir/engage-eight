# Deploying Engage Eight

Free tiers: the API on Render (Docker), Postgres on Neon, the web app on
Cloudflare Pages. Do them in this order, because each step needs a URL from
the one before.

## 1. Database: Neon

1. Create a project (Postgres 16 or newer; pick the region nearest your Render region).
2. Copy the connection string from **Connect**. It looks like
   `postgresql://user:pass@ep-xxx.region.aws.neon.tech/neondb?sslmode=require`.
   Paste it as-is. The API switches `postgresql://` to the psycopg 3 driver itself.

The API creates the tables on first start (`alembic upgrade head`).

## 2. API: Render

1. Dashboard > **New > Blueprint**, pick this repo. It reads `render.yaml`.
2. When asked, set:
   - `ENGAGE8_DATABASE_URL`: the Neon string from step 1.
   - `ENGAGE8_CORS_ORIGINS`: leave as `[]` for now, and fill it in after step 3.
3. Wait for the deploy, then open `https://<service>.onrender.com/health`.
   It should return `{"status":"ok",...}`.

`ENGAGE8_JWT_SECRET` is generated by Render. Don't set `ENGAGE8_DEBUG`.

The free tier sleeps after about 15 minutes without traffic, and the next
request takes up to a minute while it wakes. The web app shows "Waking up the
server…" while that happens. Demo accounts older than 24 hours are deleted
each time the API starts.

## 3. Web: Cloudflare Pages

1. Workers & Pages > **Create > Pages > Connect to Git**, pick this repo.
2. Build settings:
   - Framework preset: **None**
   - Root directory: `web`
   - Build command: `npm run build`
   - Build output directory: `dist`
3. Environment variables (Production):
   - `VITE_API_BASE_URL` = `https://<service>.onrender.com` (no trailing slash)
   - `NODE_VERSION` = `22`
4. Deploy. Deep links like `/quiz` work without extra config because the build
   has no `404.html`, so Pages serves the app for unknown paths.

`VITE_API_BASE_URL` is baked in at build time. If the API URL changes, start a
new Pages deployment.

## 4. Connect them

In Render, set `ENGAGE8_CORS_ORIGINS` to the Pages URL as a JSON list, for example
`["https://engage-eight.pages.dev"]` (add a custom domain here too if you use one).
Saving restarts the API.

## Check

In a private window, open the Pages URL:

- Take the quiz. It's static and works even while the API sleeps.
- Click **Try the demo**. After about 3 seconds the button says "Waking up the
  server…" if the API is cold, then it lands on Tendencies with Central HS loaded.
- On Predict, run 3rd & 8 from the 45 against Central HS. The result shows the
  opponent blend.
- If the browser console shows a CORS error, `ENGAGE8_CORS_ORIGINS` doesn't
  exactly match the page's origin (scheme, host, no trailing slash).

Then check that a forged `X-Forwarded-For` can't get around the demo limit
(10 per hour per visitor). This creates 10 demo accounts, which are deleted
after 24 hours, and uses up your own demo allowance for an hour:

```
for i in $(seq 1 12); do
  curl -s -o /dev/null -w '%{http_code} ' -X POST \
    -H "X-Forwarded-For: 203.0.113.$i" https://<service>.onrender.com/auth/demo
done; echo
```

Expect ten `201`s, then `429 429`. Twelve `201`s means the limit isn't seeing
your real IP: check that `ENGAGE8_CLIENT_IP_HEADER` is `cf-connecting-ip`.
Also look at the Render logs: a "client IP header ... is missing" warning means
the header isn't arriving and every visitor shares one limit. Fix either one
before sharing the link.
